# League Akari 魔改版设计规范

更新：2026-09-08。本文是当前设计规则的统一入口，不是界面已完成整改的声明。

适用范围：本项目新增或修改的原生页面、设置、图表、交互、数据说明和错误提示。重点是 `member-analysis` 五人局外复盘。不要据此批量重做未涉及的上游页面。

## 1. 使用与维护

- **必须**表示验收条件；**默认**表示新设计的起点，可因实际内容调整，并在现有进度文档记录原因。
- 仓库 `AGENTS.md` 保留产品与工程边界；本文集中维护设计规则；项目 Skill 负责执行方法；[README](README.md) 记录历史、修改和验收。历史方案不再作为现行设计要求。
- 数值尺寸是本项目的新设计默认值，不宣称它们都是原版 Akari 的现有尺寸，也不表示已有页面全部满足。
- 用户明确要求的设计优先于默认建议；数据真实性、隐私和产品边界不能为视觉效果让步。发现规则冲突先明确适用范围，不自行拼接两套要求。
- 修改通用规则时同步检查 UI、数据可视化 Skill 和 AGENTS 的相关表述；具体页面的临时选择不升级为所有页面的强制规则。

## 2. 产品定位与边界

- 五位朋友在游戏外看数据、比较表现、回看对局；界面应方便共同阅读，而不是尽量塞满数字。
- 保留原版 Akari 的导航、主题、控件和英雄联盟资产。原版的操作页面可以紧凑，五人复盘页可以更宽松。
- 仅支持原生 `member-analysis`。旧 `member-role-dashboard` 只作历史参考，不恢复为浏览器应用，不增加本机 HTTP 数据接口。
- 对局中不抢焦点，不遮挡游戏，不用频繁提示和动画要求用户注意；不自动执行实时游戏决策。
- 不把“相关”“同队差异”“被敌方打野参与击杀”解释成因果、配合能力或所有抓人尝试。

## 3. UI 风格：像 Akari，而不是独立网站

### 3.1 设计参考

修改前检查本地 `origin/dev` 中非 `member-analysis` 的原版实现，至少选择与任务相关的页面和组件。不要把本分支改过的五排界面当作原版依据。

| 要设计什么         | 原版参考（路径相对 `akari-src`）                                                      | 应继承什么                                 |
| ------------------ | ------------------------------------------------------------------------------------- | ------------------------------------------ |
| 页面标题与标签导航 | `src/renderer/src-main-window/components/TabbedPage.vue`、`views/toolkit/Toolkit.vue` | 简短标题、图标、清晰的当前标签、内容优先   |
| 设置表单           | `src/renderer-shared/components/SettingsRow.vue`、`SettingsSection.vue`               | 标签与控件对齐、相关设置分组、说明就近显示 |
| 主题与控件         | `src/renderer-shared/theme/naive-ui.ts`、`naive-ui-overrides/`                        | 现有控件状态、主题尺寸和颜色               |
| 页面表面与文字颜色 | `src/renderer-shared/assets/css/theme-system.css`                                     | 背景、边框、文字和壁纸遮罩的主题变量       |

参考结构，不照抄旧代码中的缺陷；特别是颜色、键盘操作和小窗口问题，仍需满足本文。

### 3.2 整体观感

**默认采用：**简洁标题、明确分组、对齐的表格、轻边框、少量强调色、适当留白。

**不要采用：**巨幅标题、宣传口号、无用途的大数字卡片、每个数字一个容器、重复嵌套卡片、额外发光和装饰性渐变。主题本身已有的背景效果可以保留，不由业务页面额外叠加。

- 一个区域用标题、间距或细分隔线即可分组时，不再增加卡片。
- 同一排控件统一高度和对齐方式；同类按钮、表格、帮助入口在各页保持一致。
- 不为五排页另造侧栏、窗口标题栏或第二套主题。主要操作使用现有 Naive UI 控件。
- 界面空间优先给比较结果与证据，而不是装饰或重复说明。

### 3.3 字体与尺寸

普通文字继承应用/系统字体；Comfortaa 仅用于品牌名称和标志。不要为分析页新增展示字体。

以下为五人复盘页的默认尺寸，单位为 CSS px；不是对上游所有窗口的全局覆盖：

| 内容                 | 默认值            | 使用要求                                   |
| -------------------- | ----------------- | ------------------------------------------ |
| 页面标题             | 16–18，半粗或粗体 | 不使用宣传页式大标题                       |
| 分组标题             | 14–16，半粗       | 同级一致，避免全部加粗                     |
| 正文、表头、主要指标 | 14                | 长时间阅读优先，不为塞入更多列缩小字号     |
| 时间、样本、次要说明 | 12–13             | 必要可见文字不得低于 12                    |
| 正文行高             | 1.5 倍左右        | 多行说明不挤压；表格不截断文字             |
| 普通控件高度         | 32 起             | 优先现有组件尺寸；小图标点击区域至少 24×24 |
| 表格行高             | 36–40 起          | 多行或英雄图标按内容增高，不固定高度裁切   |

- 名称和说明左对齐，指标右对齐；数字使用等宽数字形式（`tabular-nums`），同列保留相同精度。
- 不用低透明度代替合理层级，使样本量、单位或帮助说明难以看清。
- 长名称允许换行，或截断后在键盘可打开的详情中显示全名；关键单位不能被截断。

### 3.4 间距与形状

- 默认间距使用 4、8、12、16、24、32；图标与文字 4–8，组内 8–12，组间 16–24，页面左右 16–24，小窗口可减至 12。
- 默认只使用页面、内容分组两级背景；详情需要独立区域时，避免再套多层边框。
- 控件圆角、边框和阴影继承现有组件；自定义内容容器默认圆角 8，细边框 1，不另造夸张圆角系统。
- 面板不设无意义的固定高度；空白用于区分内容，不把简单表格拉成满屏装饰。

### 3.5 颜色与主题

颜色从现有主题变量和 Naive UI 配置取得，不在页面散布新的固定色值。新增语义颜色必须集中定义，并检查所有主题。

| 用途       | 规则                                                 |
| ---------- | ---------------------------------------------------- |
| 主要操作   | 延续 Akari 品牌强调方式，具体颜色服从当前主题配置    |
| 蓝方/红方  | 只表示队伍方位，并附“蓝方/红方”文字                  |
| 胜/负/中性 | 使用现有胜负主题颜色，附结果文字；不把零自动标成负面 |
| 警告/错误  | 配状态名称；不要把普通低样本提示做成故障警报         |
| 当前选中   | 使用边框、勾选或文字等，不能只改变颜色               |
| 五位成员   | 身份标识稳定；图中颜色变化不能使同一成员被误认成别人 |

- 已有胜负色可能与蓝红方相近，必须靠文字、图例和区域区分，不能仅靠颜色让人猜含义。
- 支持 `light`、`dark`、`butter`、`graphite`、`cyber`、`sakura`、`mint`、`aurora`；主题由 `data-theme` / `data-theme-id` 控制，不使用 `.dark` 类。
- 壁纸上先保证文字与图形清晰，必要时加强主题表面遮罩，不通过给每段文字加阴影补救。
- 本项目验收目标：普通文字对比度至少 4.5:1，关键图形、控件边界与焦点标记至少 3:1；不能仅凭“看起来还行”判断。

### 3.6 图标与图片

使用现有图标库和英雄、装备、技能、分路等游戏资产。图标用于辨认内容或动作，不随意为每个数字添加图标。不用表情符号替代产品图标，不新增无关插画。

### 3.7 统一设计语言：明确、克制、有辨识度

本项目的辨识度来自 Akari 原生控件、联盟资产和稳定的五人比较结构，而不是额外的装饰。以下规则适用于本项目维护的页面，不要求重做无关上游界面。

| 要达到的观感 | 具体做法                                                 | 避免                                     |
| ------------ | -------------------------------------------------------- | ---------------------------------------- |
| 清晰         | 标题说明比较内容，结果附近有单位和样本；常用操作直接可见 | 靠缩写、颜色或悬停才能理解               |
| 有主次       | 当前比较最突出，范围和样本次之，方法按需展开             | 所有内容都加粗、上色或放进卡片           |
| 整齐         | 同类页面共用内容起点、列对齐、图表尺寸和操作位置         | 各页各自定义表头、间距和详情样式         |
| 克制         | 中性背景承载内容，强调色只用于必要状态和当前对象         | 一项指标一种亮色；所有正数都像奖励       |
| 有游戏辨识度 | 用英雄图标、分路标记、蓝红方文字辅助辨认                 | 电竞海报式发光、巨幅背景、无意义战力评分 |

发生取舍时按“数据真实 → 能读懂和操作 → 比较方便 → 视觉修饰”处理。美观不能依靠隐藏缺失、裁掉长名称或缩小必要文字实现；同样，数据准确也不是忽略排版的理由。

### 3.8 组件外观与信息层级

- **页头**：页面身份和主要操作集中在一处。一个操作区域默认只有一个主要按钮；普通筛选、展开、帮助使用次要样式。刷新不可用时提供原因，而不只变灰。
- **内容分组**：标题与内容左边缘对齐，操作在标题同行靠右；放不下就另起一行。不用装饰图标、色条和边框同时重复强调一个标题。
- **数据行**：固定顺序为“对象 → 结果 → 样本或状态 → 操作”。姓名、英雄图标和分路形成稳定的身份区域；数值变化不改变身份的宽度和位置。
- **表格**：表头与数据共享列对齐；默认用轻分隔线，不给每个单元格画粗框。悬停辅助定位整行，选中另有明确标记；非选中行仍正常可读。
- **卡片**：只用于独立对象或独立任务，例如一场对局、一个设置分组；不为每个数字单独造卡片。已有标题和间距能分组时不加背景。
- **详情**：短解释用提示层，少量指标就地展开，多项设置使用抽屉；确认删除或放弃输入才用对话框。不要为了显示一个定义打开大面板，也不要层层叠加抽屉。
- **图标和图片**：同类图标尺寸一致、与文字垂直对齐；头像预留空间，加载失败显示占位和名称，不让整行跳动。不把点击动作藏在没有说明的英雄头像上。
- **留白**：用组间距离区分内容，用组内距离表达关联。不要为了“填满窗口”放大图表或拉开五位成员，也不把所有空隙压掉来塞入更多列。

尺寸、字体、圆角和色值继续使用 3.3–3.5 的规则。页面不得另设一套“紧凑版字号”或独立调色板；只有明确的内容需求才增加组件变体，并统一用于同类页面。

### 3.9 图表的共同外观

这里规定图表怎样保持一致；选什么图、如何计算及如何表达缺失仍由第 7 节负责。

- **固定构成**：图名和简短范围在上，图形居中，必要图例就近，查看精确值与对局的入口在下。不要将图例隔在另一个大区域。
- **视觉顺序**：数据标记最清楚，坐标和单位次之，辅助网格最轻；零线或明确基准比普通网格更醒目。减少无用网格，不删掉理解尺度所需的参照。
- **标记一致**：同类条形粗细一致，同类点图使用一致的点大小和区间线。点的大小若不表示实际数据，不得随意变化来突出某人。
- **标注一致**：同图相同单位保持相同精度；长标签优先换行，不默认倾斜或旋转。数值不与区间线、柱端和其他标签重叠，画布预留标注空间。
- **强调一致**：通常以统一中性色或主题色比较数值，仅突出用户选中的对象。确需多种身份颜色时稳定复用并附姓名；颜色不能同时代表成员和好坏。
- 选中、悬停与键盘焦点分别处理：选中使用轻底色及文字标记，不叠加发光、动画外圈或多重边框；键盘焦点保留单层清晰细线。分析页普通按钮与分段选项统一 6px 圆角，不覆盖圆形图标按钮和开关形状。
- **状态一致**：缺失位置使用文字说明而非假条形；极值保留，必要时改变图形或增加精确值入口，不能无提示截断。重叠点显示数量并能展开成员。
- **尺寸一致**：同一屏直接比较的图共享绘图区和尺度；不同图不机械等高。横条高度由行数决定，散点图给两轴留足空间；缩放时调整排版，不把整张 SVG 连同文字无限缩小。
- **图表与表格一致**：同一指标在图、表、详情中使用相同名称、单位、格式和筛选范围；选中对象相互对应，不出现图选了甲、详情仍显示乙。

### 3.10 状态、动作和文字的共同表达

| 状态       | 外观与反馈                                               | 不应出现                             |
| ---------- | -------------------------------------------------------- | ------------------------------------ |
| 默认       | 清楚可读，操作有一致的按钮或链接外观                     | 所有元素都像可点击                   |
| 悬停       | 局部背景或边界变化，保持位置稳定                         | 放大、移动导致邻项抖动               |
| 键盘焦点   | 独立清晰的焦点边界，不能被固定区域遮住                   | 只有鼠标操作有反馈                   |
| 选中       | 标记或边界加适度背景，与悬停明显不同                     | 只换颜色，或把其他成员淡到看不清     |
| 不可用     | 保留可读标签，就近解释限制                               | 把无数据、加载和禁用都显示成灰色空白 |
| 处理中     | 标明动作和真实阶段，防止重复提交；可取消任务保留取消入口 | 整页闪烁、伪造进度、仍显示可重复提交 |
| 成功或失败 | 说明发生了什么；失败给出重试或修正入口                   | 只给图标、错误码或瞬间消失的重要信息 |

- 动作名称固定使用“刷新、取消刷新、查看对局、展开、收起、保存、重试”等直接表达；同一动作不在不同页面交替叫“查看、分析、探索”。
- 默认状态只显示必要内容；低样本是分析限制，不是系统故障。普通成功反馈不占用长期横幅，影响结果的失败不能仅用短暂提示。
- 用语描述观察而非评价成员，例如“15 分钟经济差”，不写“压制力”；无证据不写“最佳搭档”“必胜组合”。完整指标名称首次可见，缩写仅作辅助。
- 动画沿用第 5 节，只解释展开、选择和任务状态；图表切换不让数值从零逐个滚动，不用动画夸大领先幅度。

新增或修改页面交付前，检查：它与相邻页面是否使用同样的标题、筛选、身份行、图表标注、详情入口和反馈？若有差异，能否用实际任务差异解释，而不是“这一页想换种风格”？

## 4. 页面结构与阅读顺序

### 4.1 通用顺序

1. 页面名称与主要操作。
2. 当前成员、时间/版本、比赛范围、筛选和样本。
3. 当前页主要比较，优先一张明确的表或图。
4. 选中项的具体数值与对局证据。
5. 次要定义和方法说明。

- 常用筛选直接可见，高级筛选可折叠；启用后仍显示已用条件和清除入口。
- 数据范围在页级统一显示，不在每个小面板重复。但某指标有效场数不同，必须就近注明。
- 不恢复已移除的总览页，不因本规范新增功能。下表是下一次修改相关页面时的默认设计目标，不改变已有计算和筛选行为。

### 4.2 五排各页默认设计

| 页面/内容            | 首先回答                         | 默认展示与顺序                                                   | 进一步查看                             |
| -------------------- | -------------------------------- | ---------------------------------------------------------------- | -------------------------------------- |
| 成员分路             | 同一分路下，各成员表现如何？     | 分路按上、野、中、下、辅；成员按设置中的固定顺序；比较同单位指标 | 选中成员分路查看指标和对局             |
| 英雄池               | 各成员在各分路使用哪些英雄？     | 成员和分路顺序稳定；英雄默认按场数降序，不以少量对局的胜率排第一 | 英雄的胜负、有效场数和对局             |
| 组合                 | 同一组合有哪些观察结果？         | 组合类型分组，默认按场数降序；观察差值与场数并列                 | 组合定义、计算方法和涉及对局           |
| 打野、事件、前期转化 | 发生了什么，之后出现了什么结果？ | 每组只回答一个问题；事件数、有效次数、比率放在一起               | 时间、地点、事件顺序与对局             |
| 被抓统计             | 对线期哪些死亡有敌方打野参与？   | 分路和成员固定顺序；有效场次、次数、场均、涉及对局率             | 按时间查看事件，写明不统计未死亡的抓人 |
| 对局列表             | 哪些对局支持当前观察？           | 默认最新在前，保留筛选范围                                       | 对局与事件详情                         |

- 排名视图允许按指标排序，并明确排序方向；并列不假装存在高低。切换排序不改变成员身份颜色。
- 首次进入默认不替用户挑一个“最好”的成员。详情必须有选中项时可选第一个有效项，并明显标识。
- 同一会话切换标签、刷新应保留仍有效的筛选和选择；筛选后选中项消失时明确清空并提示，不能显示旧详情。
- 版本升级不静默修改用户已保存的范围或排序；新增默认行为需单独实现并验证。

## 5. 小窗口、滚动与交互

- 按实际内容区宽度布局，不只按显示器分辨率。双栏放不下时改为上下排列；筛选允许换行。
- 不用缩小字体解决溢出。长表格可在独立表格区域横向滚动，成员/分路列和表头按需固定；页面主体不能整体横向溢出。
- 尽量只有一个主要纵向滚动区。固定标题和筛选不能占据小窗口大半高度，也不能遮挡键盘焦点。
- 关闭详情或设置后回到原来的触发控件；Escape 可关闭可关闭层。表单有未保存内容时，不静默丢弃。
- 图表的选择、帮助、筛选和详情均有键盘操作；焦点可见。主要结论不只藏在鼠标提示里，也不要求把所有细节永久印在图上。
- 刷新显示真实阶段/进度并可取消；无法测定比例时不要伪造百分比。刷新失败或取消保留上一版完整数据。
- 不在刷新完成时突然重排正在阅读的行、抢焦点或跳到顶部；必须更新的上下文清晰提示。
- 动画只用于说明状态或切换，默认不超过约 200ms；已有共享组件不为此单独改造。遵循减少动态效果设置，禁用非必要过渡。

## 6. 文案与完整状态

文字只说明名称、数据、操作、定义和状态，不讲设计理由、开发过程或请求历史。完整句子及标点交给翻译文件；不要拼接多段句子破坏语序。

| 状态       | 必须让用户知道       | 示例                             |
| ---------- | -------------------- | -------------------------------- |
| 首次使用   | 下一步做什么         | 尚未配置成员；配置成员           |
| 加载       | 正在处理什么         | 正在读取分析数据                 |
| 筛选无结果 | 数据不是损坏了       | 当前条件下没有对局；清除筛选     |
| 部分数据   | 哪部分未纳入         | 20 场中有 16 场包含此项数据      |
| 旧数据     | 是否仍可看、如何更新 | 当前显示上次结果；刷新数据       |
| 刷新失败   | 影响与下一步         | 刷新失败，已保留上一版数据；重试 |
| 不适用     | 不是零也不是错误     | 此项不适用于打野位               |
| 真正为零   | 有有效观察但没发生   | 0 次（有效 20 场）               |

- 原始错误码、堆栈、worker、staging 等不直接显示；详情也不得暴露凭据和玩家原始数据。
- 不使用“总语料”等内部称呼，优先“已收集对局”“筛选后”“当前分析”。
- 指标解释默认一句话，可展开方法。不要在没有依据时把指标改成更容易理解但不准确的名字。
- “同队胜率偏差”解释应写清它与哪一个基准比较；“收缩后差值”说明少量对局的差值会向基准调整，具体以实现为准。两者都不代表配合能力，也不保证未来胜率。
- 95% 区间的帮助可说明“用于表示估计的不确定程度，越宽越不确定”，不要解释成下一局胜率保证。

## 7. 数据与图表

### 7.1 每个指标必须先定义

在类型、计算代码或长期技术文档中维护：含义、原始来源/计算方式、有效对局、分子/分母、时间/版本/比赛模式/分路、单位、精度、缺失处理和比较限制。界面用简短文字展示影响理解的部分。

- 缺失、未采集、不适用、过期、部分有效与零必须分开；分母为零不显示 0%。
- 来源未知写“来源未知”，不能为了界面完整而编造来源；估算值必须标注为估算。
- 比率优先同时展示百分比及分子/分母；不同指标的有效场数不能借用页面总场数。
- 百分比默认 1 位小数，次数为整数，场均默认 1 位小数，时间明确秒或分:秒；计算保留原始精度，只在显示时舍入。比率差标“百分点”，不与相对变化百分比混用。
- 不跨分路直接判断伤害、补刀等指标谁更优秀；跨版本或不同样本范围比较需注明差异。

### 7.2 样本量与结论

- 不规定一个适用于所有指标的“够准场数”。每项指标记录低样本提醒条件及理由；未定义时只显示实际有效数和可用区间，不宣称稳定。
- 默认不从少量样本产生“最佳”“最差”“提升”“下降”等能力结论。明确的数值排序可以保留，但叫“按某指标排序”，而不是能力排名。
- 比率按适用方法展示区间；不能把胜率区间算法套用于场均和差值。方法不适用或数据不足时说明未计算，不生成假区间。
- 5 场 4 胜和 100 场 80 胜都为 80%，但必须能看出样本和不确定程度不同。

### 7.3 图形选择与统一尺度

- 精确查数用表；成员比较优先对齐表格、条形或点图；趋势用折线；地图仅展示实际空间事件。
- **柱形和条形以零为基线，不截断。**需要放大微小差异时改用标清范围的点图或折线，而不是截短柱形。
- 同单位、同目的的直接比较使用同一尺度；经济差等有正负的指标明确画零线。不同单位不共用长度或双轴制造关联。
- 时间线保留时间顺序，缺失段不画成连续有效观察，跨版本标出边界。
- 雷达图、桑基图、关系图等不是默认方案；只有比简单图表更能说明具体关系时才采用，并在内部记录理由及精确数值查看方式。
- 图例、坐标、单位、选中身份必须可见或有直接可用的替代入口。颜色之外再用文字、位置、线型或符号区分。

## 8. 工程、性能与隐私设计

- 保留 Electron + Vue 3 + Naive UI 技术路线。显示组件接收明确类型的数据，不从文案反推含义，不在渲染循环里重新聚合大批对局。
- 成员分析数据仅经允许的 Electron IPC 读取；渲染端不直接读文件、拼接任意接口或获得令牌。
- 运行数据仅在 Electron `userData` 下；禁止提交或上传真实比赛数据、生成数据集、凭据、日志和缓存。截图和测试采用合成或匿名数据。
- 长任务可取消，新旧任务结果隔离，完整结果就绪后再替换旧版。刷新、切页、缩放和换主题不重复注册监听或泄漏图表实例。
- 不因规范整理新增依赖、服务、发布流程或导出能力。工程细节按对应项目 Skill、当前数据契约和维护手册执行；早期技术设计只用于追溯。

## 11. 前端统一改版方案（2026-09-06，待用户确认）

状态更新（2026-09-07）：用户已授权开始实施，最终视觉仍待人工确认；标题保留原方案日期与链接。英雄池按本轮反馈保留分路分栏与小圆环，不为统一图形而替换用户认可的布局。本文是方案唯一维护位置，README 只记录检查和状态。

### 11.1 目标与取舍

- 让用户依次看清“比较谁、什么范围、数值差多少、有多少依据、哪些对局支持”。
- 保留 Akari 导航、字体、控件、游戏图标和八主题。主要特征是五位成员对齐比较，而不是卡片数量或图表种类。
- 每页一个主要比较区域；明确数值紧邻图形，详细指标与对应对局按需展开。不是每页再增加一张图和一张重复大表。
- 不新增总览、综合能力分或配合评分；不默认使用雷达、关系网络、桑基图或热力图。没有可靠坐标就不画地图，没有连续记录就不画趋势。

### 11.2 所有页面共用的结构

```text
成员分析                                      更新时间  刷新  设置
页面标签（沿用现有功能；窄窗口可滚动，当前页始终可见）
最近场数  蓝红方  结果  搜索  更多筛选
当前分析 30 场 · 版本 26.1 · 来源；已用筛选及清除入口
本页比较条件，例如：分路 / 指标 / 排序
主要比较图或表：身份 ｜ 图形与数值 ｜ 有效样本 ｜ 查看对局
选中项详情与对应对局（默认不展开；窄窗口放在主比较下方）
```

- 不重复显示页签同名大标题。页面总场数集中显示一次，指标自己的有效场数不能省略。
- 顶部提示默认一行摘要加“详情”；错误、影响计算的缺失信息不可隐藏。首次使用保留明确配置入口。
- 标题和标签可固定，筛选及普通说明随主要内容滚动；不把所有顶部区域一起固定。
- 主要文字 14px，次要文字 12–13px，标题 16–18px，控件至少 32px；间距和颜色沿用第 3 节，不另立数值系统。
- 成员按设置顺序，分路按上野中下辅。明确选择排序时才改变行顺序；并列不强行排名。
- 常用宽度可并排展示详情，但主比较列宽不足时直接上下排列；不缩字、不压缩图表标签、不让页面整体横向滚动。

### 11.3 统一图形与数值表达

下表为通用默认；成员分路主比较采用用户已认可的 11.8 竖向方案，同尺度、零线和缺失值规则不变。

- 不同量纲不共用长度。胜率差写“百分点”，经济写“金币”，时刻写“15 分钟”，避免只写 `GD@15` 等缩写。
- 同类图共用尺度、刻度、数字精度和选中样式。禁止用最小条长夸大零值；点图非零起点必须有清晰刻度。
- 每个图组就近提供一次简短图例，例如“圆点为胜率，短线为 95% 区间”；不能只留下无刻度的小横线让人猜。

- `0 次（有效 20 场）`、`— 未采集`、`— 不适用`、`有效 16/20 场`分开显示。数据缺失不参与均值，也不在图上落到零点。
- 少量样本保留显示、明确提醒，不因切换最近 20/50/100 场而静默隐藏类别。若提供最低场数筛选，必须可见且显示排除数量。
- 没有适用的不确定性计算方法时不画假区间；同局内事件不能未经验证就当成独立对局套胜率算法。

### 11.5 交互和状态统一

- 视觉检查必须覆盖点击后的展开、选择、弹层、保存失败与关闭状态，不能只检查默认首屏。详情与工具栏滚动后不被固定页签遮挡；新增输入、需要确认的操作和错误反馈应能立即找到，关闭后恢复合理焦点。

- 点击图形与点击表格行选中同一对象；再次取消后保持未选中，不自动选回第一项。
- 同会话切页保留有效的指标、筛选、排序和选择；条件变化导致选择消失时清空并说明，不显示旧详情。
- 帮助支持点击、键盘和关闭，不只依赖鼠标悬停或原生 `title`。退出详情回到原触发项。
- 刷新时继续看上一版结果，显示真实阶段；成功后明确数据更新，不突然跳滚动位置。失败可重试且保留数据。
- 设置按成员、采集范围、存储分组。字段错误就近显示；保存成功才关闭；关闭未保存输入时询问是否放弃。
- 未配置、加载、筛选无结果、部分数据、旧数据、失败、零值、长名称均按同一套状态规则处理。

### 11.6 实施顺序与通过条件

当前执行顺序更新：此前纯表格及双图方案停用；用户已认可 11.8 的新样板，现先接入成员分路，再逐页改造。以下工程与验收要求仍适用，样板认可不等于全部页面完成。

1. **数据表达先行**：补齐缺失值与有效分母，阻止无意义的同队比较，修正零值、单位和重叠点。前端无法从已被填零的数据恢复缺失，必须配套修正计算与兼容。
2. **统一页面与组件**：范围栏、指标定义、比例与区间、差值图、成员行、证据入口及详情采用同一实现；先接入已认可的成员分路样板；英雄池保留原结构，不因统一组件重新排版。
3. **覆盖其余页面**：按逐页表改造，保留功能和既有数据范围；三个更名、默认列和排序需随方案确认，不自行附加功能。
4. **视觉验收**：按第 9 节检查八主题、常用/最小窗口、125% 放大、键盘及完整边界状态。正常状态的小窗口首屏必须出现实际比较行，而不只有标题和筛选；长图必须能同时识别图意、单位和对象。

重点补拍：樱花主题选中按钮、散点同值重叠、英雄多类别、同队全零、各图零/缺失/低样本、长名称、红蓝拆分及设置失败。此前合成截图主要为首屏且带旧数据提示，不足以证明这些状态已通过；当前为“实施中，最终视觉待确认”。

### 11.8 已认可方向：同一画布中的五人比较（逐步接入）

此前纯表格、双图和静态概念稿均被用户否定，不推广。用户已认可本节代码样板并要求继续；先接入正式成员分路页，其余页面分步调整，英雄池保持原结构。认可视觉方向不等于完成原生验收。

- 复用原生标题与标签的同排结构、系统字体、分路图标与 Naive 控件；其他分析页面沿用同一主题底色、控件与详情样式，不把所有数据强行改成同一种图；范围一行展示，已生效筛选在收起控件后仍可见。
- 本样板采用一个共用尺度的竖向比较区，五位成员按设置顺序横向对应。经济差从零开始，负值向下；可切换参团率的 0–100% 尺度。不把单个成员的小图分别缩放。
- 每列下方直接对应成员、有效样本、胜负、胜率区间、KDA 与参团率；姓名可展开详情。数字圆标使用配置中的成员序号，筛选后不重新编号；不是成绩排名，也不冒充真实头像。
- 常规示例继续使用原有合成数据和实际聚合，不调整成绩使图形更好看。另设边界场景覆盖零、缺失、1/6 有效样本、极值、长名称及筛选无结果。
- 外层不横向溢出；需要时仅比较区横向滚动，保留字号和共同刻度。长名称换行后，后续指标仍横向对齐。主比较标签必须给极值留足空间。低高度窗口中，若列下姓名在首屏外，数值旁应补充成员姓名，不能让可见数据失去身份对应。
